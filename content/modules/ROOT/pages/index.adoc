= RHOAI Community Dashboards

Community-maintained Perses and Grafana dashboards for {rhoai}, kept in Git and deployed with `oc apply`.

* Every dashboard is a Kubernetes resource: reviewed, versioned, and rolled back like any other manifest
* Built on the datasource that ships with the {rhoai-short} Monitoring Stack, so there is nothing extra to deploy
* One deployment path for all dashboards: no Helm for one and Kustomize for the next

IMPORTANT: Dashboards in this repository use the out-of-the-box datasource supplied by the {rhoai-short} Monitoring Stack (`{perses-ds}`). That single constraint is what makes them portable: a dashboard here works on any cluster with the Monitoring Stack enabled, with no exporters, recording rules, or datasource wiring to set up first. Dashboards that need more than that are still welcome: they are linked from the xref:custom-dashboards.adoc#_dashboard_register[dashboard register] and maintained by their authors.

== Why RHOAI Community Dashboards

The {rhoai-short} console ships a handful of dashboards covering models, serving traffic, and utilization. They answer the questions the product team anticipated. They do not answer "is the queue depth on *our* summarization service drifting again", because that question is specific to your models, your naming, and your organization.

Keeping those answers in Git rather than clicking them together in a UI means they survive a cluster rebuild, get reviewed before they reach anyone's screen, and can be shared across teams as a pull request instead of a screenshot.

== Requirements

* {rhoai-short} 3.5 or later with the Monitoring Stack enabled, on an {ocp-short} version that release supports
* {coo} installed, which provides the Perses CRDs
* `oc` authenticated as `cluster-admin`, or with edit rights on the `{monitoring-ns}` namespace

xref:deploy-perses.adoc#_verify_the_monitoring_stack[Verify the Monitoring Stack] has the commands to confirm all of this before you apply anything.

== User Workload Monitoring is deprecated

NOTE: From {rhoai-short} 3.6 onwards, {uwm} is no longer referenced in the {rhoai-short} documentation. The link:https://github.com/rh-aiservices-bu/rhoai-uwm[rhoai-uwm] repository remains available for existing 3.5 and earlier deployments, but new work should target the {rhoai-short} Monitoring Stack and this repository. If you are planning an upgrade, migrate to the Monitoring Stack rather than carrying {uwm} forward.

== Support

Dashboards here are community contributions, not Red Hat supported product content. Validate the queries, the metric names, and the access controls against your own cluster before you put a dashboard in front of anyone who will make decisions with it.
